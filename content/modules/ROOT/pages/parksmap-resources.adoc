= 리소스 관리와 쿼터
:navtitle: 리소스 관리와 쿼터

include::vars.adoc[]

프로젝트를 처음 만들 때 살펴봤듯이, 각 Project는 리소스 쿼터나 제한 같은 제약 조건을 가질 수 있습니다. 지금까지는 `parksmap`을 자유롭게 스케일링했지만, 실제 클러스터는 유한한 자원입니다. 이번 섹션에서는 컨테이너 하나가 사용할 수 있는 자원을 제한하는 방법과, 프로젝트 전체가 사용할 수 있는 총량을 제한하는 방법을 배웁니다.

[#requests_and_limits]
== 배경 지식: Requests와 Limits

컨테이너마다 CPU와 메모리에 대해 두 가지 값을 지정할 수 있습니다:

* *Requests*: 스케줄러가 Pod를 배치할 노드를 고를 때 "이 정도는 반드시 확보해 달라"고 보장을 요청하는 값입니다. 요청한 만큼의 자원 여유가 없는 노드에는 Pod가 스케줄링되지 않습니다.
* *Limits*: 컨테이너가 사용할 수 있는 *최대치*입니다. CPU limit을 초과하면 컨테이너는 스로틀링(제한)됩니다. 메모리 limit을 초과하면 컨테이너는 OOMKilled(Out Of Memory) 상태로 강제 종료됩니다.

link:{ocp4_starter_openshift_docs}/html/nodes/working-with-clusters#understanding-resource[Requests와 Limits에 대한 문서,window='_blank']에서 더 자세히 알아볼 수 있습니다.

[#configuring_resources]
== 실습: Deployment에 Requests/Limits 설정하기

`parksmap` Deployment에 requests/limits를 설정해 보겠습니다. 웹 콘솔의 *Topology* 화면에서 `parksmap`을 클릭하고 _Actions → Edit Deployment_를 선택한 후 YAML 에디터에서 각 컨테이너의 `resources` 항목을 다음과 같이 채우거나, CLI를 사용할 수 있습니다. 원하는 방법을 선택하세요.

[source,role="copypaste"]
----
oc set resources deployment/parksmap --requests=cpu=100m,memory=128Mi --limits=cpu=200m,memory=256Mi
----

적용된 값을 확인합니다:

[source,role="copypaste"]
----
oc describe deployment parksmap | grep -A 4 Limits
----

[.console-output]
[source]
----
    Limits:
      cpu:     200m
      memory:  256Mi
    Requests:
      cpu:      100m
      memory:   128Mi
----

[#resource_quota]
== 배경 지식: ResourceQuota

*Requests*/*Limits*가 Pod 하나에 대한 제약이라면, *ResourceQuota*는 Project(namespace) *전체*에 대한 총량 제약입니다. 예를 들어 "이 프로젝트에서 동시에 실행되는 Pod는 최대 6개, 요청 가능한 CPU 합계는 1코어까지"처럼 제한할 수 있습니다. 여러 팀이 하나의 클러스터를 공유할 때, 한 프로젝트가 자원을 독점하지 못하도록 막는 안전장치입니다.

[#create_resource_quota]
== 실습: ResourceQuota 생성하기

ResourceQuota를 새로 만들기 전에, 이 namespace에 이미 적용된 쿼터나 제한이 있는지 먼저 확인하는 것이 좋은 습관입니다:

[source,role="copypaste"]
----
oc get resourcequota,limitrange
----

NOTE: 클러스터 관리자가 플랫폼 차원에서 이미 쿼터를 설정해 두었을 수 있습니다. 이미 쿼터가 있다면, 아래 예시의 숫자가 기존 쿼터보다 커서 효과가 없을 수 있으니 실습 환경에 맞게 숫자를 조정하세요.

*Workloads* → *ResourceQuotas*에서 *Create* → *From YAML*을 선택하고 다음 YAML을 붙여넣습니다:

[source,role="copypaste",subs="attributes"]
----
apiVersion: v1
kind: ResourceQuota
metadata:
  name: workshop-quota
  namespace: {ocp4_starter_project}
spec:
  hard:
    requests.cpu: "1"
    requests.memory: 1Gi
    limits.cpu: "2"
    limits.memory: 2Gi
    pods: "6"
----

*Create*를 클릭합니다. 적용된 쿼터와 현재 사용량을 확인합니다:

[source,role="copypaste"]
----
oc describe resourcequota workshop-quota
----

[#quota_in_action]
== 실습: 쿼터 한도에서 스케일링해보기

이제 `pods: "6"` 한도에 부딪힐 때까지 `parksmap`을 스케일링해 보겠습니다. 현재 이 프로젝트에는 `parksmap`, `nationalparks`, `mongodb` Pod가 이미 실행 중이므로, 여유는 얼마 남지 않았습니다.

[source,role="copypaste"]
----
oc scale --replicas=6 deployment/parksmap
----

Pod와 ReplicaSet 상태를 확인합니다:

[source,role="copypaste"]
----
oc get rs -l app=parksmap
oc get events --field-selector reason=FailedCreate
----

[.console-output]
[source]
----
LAST SEEN   TYPE      REASON        OBJECT                        MESSAGE
10s         Warning   FailedCreate  replicaset/parksmap-79d5c9f8a2   Error creating: pods "parksmap-79d5c9f8a2-x8k2p" is forbidden: exceeded quota: workshop-quota, requested: pods=1, used: pods=6, limited: pods=6
----

`exceeded quota` 메시지를 통해 ResourceQuota가 실제로 새 Pod 생성을 막고 있음을 확인할 수 있습니다. *ReplicaSet*은 요청받은 개수(`DESIRED`)를 계속 유지하려고 시도하지만, 쿼터 때문에 실제로는(`CURRENT`) 그보다 적은 Pod만 만들어집니다.

계속 진행하기 전에, `parksmap`을 다시 인스턴스 1개로 스케일 다운하세요:

[source,role="copypaste"]
----
oc scale --replicas=1 deployment/parksmap
----

WARNING: Pod를 1개로 스케일 다운하지 않으면 이후 섹션에서 예기치 않은 동작이 발생할 수 있습니다.
