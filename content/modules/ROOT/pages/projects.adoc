== OpenShift Project 이해하기

Project는 배포를 구성하고 관리하는 데 도움을 주는 OpenShift의 핵심 개념입니다. OpenShift Project를 사용하면 한 그룹의 사용자(또는 개인 사용자)가 다른 그룹과 분리된 상태로 자신의 콘텐츠를 구성하고 관리할 수 있습니다. 각 Project는 고유한 리소스, 정책(누가 어떤 작업을 수행할 수 있는지 정의), 제약 조건(리소스에 대한 쿼터 및 제한 등)을 가집니다.

Project는 여러분(또는 여러분의 팀)이 작업에 사용하는 모든 애플리케이션 서비스와 엔드포인트를 감싸는 "래퍼(wrapper)"라고 생각하면 됩니다. 내부적으로 OpenShift Project는 Kubernetes 네임스페이스(namespace) 위에 구축되지만, Project 추상화는 관리자에게 향상된 역할 기반 접근 제어(RBAC) 같은 추가 기능을 제공합니다.

이 섹션에서는 웹 콘솔과 명령줄 인터페이스를 모두 사용하여 Project로 작업하는 방법을 살펴봅니다. 모든 용어를 이해하지 못해도 걱정하지 마세요 - 이러한 개념은 워크숍 전체에 걸쳐 자세히 다룰 것입니다.

== 웹 콘솔에서 Project 살펴보기

**{ocp4_starter_project}**라는 이름의 Project가 이미 여러분을 위해 생성되어 있습니다. 이 페이지 오른쪽의 **OCP Console** 탭을 통해 살펴보는 것부터 시작해 보세요.

OpenShift 웹 콘솔에 로그인한 후, Project 드롭다운에서 여러분의 Project를 찾아 선택합니다. Project 개요를 살펴보면서 Project의 리소스와 활동에 대한 요약을 확인해 보세요.

=== Topology 뷰

Project 내의 애플리케이션과 그 구성 요소를 시각적으로 표현해 주는 Topology 화면을 살펴보세요.

왼쪽 메뉴에서 **Workloads**로 이동한 후 **Topology**를 선택합니다.

[.bordershadow]
image::openshift-console-topology.png[애플리케이션 구성 요소를 시각적으로 보여주는 Topology 화면,link="self",window=_blank]

아직 아무것도 배포하지 않았기 때문에 현재는 애플리케이션이나 구성 요소가 보이지 않습니다. 워크숍을 진행하면서 이 **Topology** 화면에서 애플리케이션의 구성 요소를 시각화하고 상호작용할 수 있게 됩니다.

== 명령줄로 Project 다루기

OpenShift CLI를 사용해서도 Project와 상호작용할 수 있으며, 이를 통해 자동화 기능과 고급 기능에 접근할 수 있습니다.

웹 터미널에서 다음 명령을 사용하여 여러분의 Project로 전환합니다:

[source,bash,role="copypaste",subs="attributes"]
----
oc project {ocp4_starter_project}
----

다음과 유사한 출력이 표시됩니다:

[.console-output]
[source,subs="attributes"]
----
Now using project "{ocp4_starter_project}" on server "{ocp4_starter_api_url}"
----

이 명령은 현재 컨텍스트를 여러분에게 할당된 Project 내에서 작업하도록 설정합니다. 별도로 지정하지 않는 한, 이후의 모든 ``oc`` 명령은 이 Project 범위 내에서 동작합니다.

== 다음 단계

이 워크숍 전체에 걸쳐 웹 콘솔과 명령줄 인터페이스를 모두 사용하여 Project 내에서 애플리케이션을 배포하고 관리합니다. 웹 콘솔은 일반적인 작업을 위한 직관적인 시각적 인터페이스를 제공하며, CLI는 더 고급 작업을 위한 자동화 기능을 제공합니다.

이제 Project와 그것에 접근하는 두 가지 방법에 익숙해졌으니, 애플리케이션 배포를 시작할 준비가 되었습니다!
