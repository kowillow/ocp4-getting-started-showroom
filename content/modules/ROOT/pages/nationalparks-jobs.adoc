= 일회성 작업과 예약 작업: Job과 CronJob
:navtitle: 일회성 작업과 예약 작업: Job과 CronJob

include::vars.adoc[]

지금까지 ``/ws/data/load``를 브라우저에서 직접 열어 데이터를 적재했습니다. 이런 일회성 작업을 사람이 매번 브라우저를 열어 수행하는 대신, Kubernetes 오브젝트로 자동화해 보겠습니다. 이어서 CronJob을 예약 실행이 아니라 필요할 때마다 버튼 클릭으로 재사용할 수 있는 템플릿으로 활용하는 방법도 살펴보겠습니다.

[#job_automation_group]
== Job으로 자동화하기

[#jobs_and_cronjobs]
=== 배경 지식: Job과 CronJob

**Deployment**는 Pod가 항상 실행 중인 상태를 유지하도록 설계되었습니다. 하지만 "한 번 실행하고 끝나는" 작업, 예를 들어 데이터 마이그레이션이나 배치 처리에는 어울리지 않습니다. 이런 작업을 위한 오브젝트가 **Job**입니다.

* **Job**은 지정된 완료 조건(기본은 1회 성공)을 만족할 때까지 Pod를 실행합니다. 실패하면 ``restartPolicy``와 ``backoffLimit`` 설정에 따라 재시도하며, 잠시 후 실습에서 구체적인 값을 지정해 보겠습니다.
* **CronJob**은 cron 표현식(분 시 일 월 요일 형식의 5개 필드로 지정)으로 지정한 일정에 따라 Job을 반복 생성합니다.

Deployment(상시 실행, 재시작하면 안 됨)와 Job(완료되면 끝, 재시작 대신 재시도)의 차이를 기억해 두면 어떤 상황에 무엇을 쓸지 결정하기 쉬워집니다.

[#automate_data_load]
=== 실습: 데이터 적재를 Job으로 자동화하기

**워크로드(Workloads)** → **작업(Jobs)**에서 **작업 만들기(Create Job)**을 선택하고 다음 YAML을 붙여넣습니다:

[source,yaml,role="copypaste",subs="attributes"]
----
apiVersion: batch/v1
kind: Job
metadata:
  name: nationalparks-data-load
  namespace: {ocp4_starter_project}
spec:
  backoffLimit: 2
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: load-data
          image: registry.access.redhat.com/ubi9/ubi-minimal:latest
          command:
            - curl
            - "-sf"
            - "http://nationalparks.{ocp4_starter_project}.svc.cluster.local:8080/ws/data/load"
----

[.bordershadow]
image::nationalparks-job-create.png[Job Create From YAML 다이얼로그,link=self,window=blank]

**Create**를 클릭합니다. Job 상태를 확인합니다:

[source,bash,role="copypaste"]
----
oc get jobs
----

[.console-output]
[source]
----
NAME                       COMPLETIONS   DURATION   AGE
nationalparks-data-load    1/1           3s         12s
----

Pod의 로그를 확인해 실제로 어떤 응답을 받았는지 확인합니다:

[source,bash,role="copypaste"]
----
oc logs job/nationalparks-data-load
----

[.bordershadow]
image::nationalparks-job-logs.png[완료된 Job Pod의 로그 확인,link=self,window=blank]

[#cronjob_as_template]
== 실습: CronJob을 데이터 적재 템플릿으로 활용하기

앞서 만든 ``nationalparks-data-load`` Job은 1회성입니다. 나중에 데이터를 다시 적재하고 싶다면 어떻게 해야 할까요? Job의 스펙은 대부분 수정할 수 없으므로, 같은 작업을 다시 실행하려면 매번 삭제하고 새로 만들거나 이름을 바꿔 다시 생성해야 합니다.

이럴 때 **CronJob**을 "예약 실행"이 아니라 **재사용 가능한 템플릿**으로 활용하는 방법이 있습니다. 스케줄을 실제로는 절대 도래하지 않는 시각(예: 존재하지 않는 2월 31일)으로 지정해 두면, CronJob은 자동으로는 절대 실행되지 않지만, 웹 콘솔에서 버튼 클릭 한 번으로 이 템플릿을 이용해 새 Job을 언제든 수동으로 만들어낼 수 있습니다.

**워크로드(Workloads)** → **CronJobs**에서 **CronJob 만들기(Create Cronjob)**을 선택하고 다음을 붙여넣습니다.

[source,yaml,role="copypaste",subs="attributes"]
----
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nationalparks-data-load-template
  namespace: {ocp4_starter_project}
spec:
  schedule: "0 2 31 2 *"
  jobTemplate:
    spec:
      backoffLimit: 2
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: load-data
              image: registry.access.redhat.com/ubi9/ubi-minimal:latest
              command:
                - curl
                - "-sf"
                - "http://nationalparks.{ocp4_starter_project}.svc.cluster.local:8080/ws/data/load"
----

NOTE: ``schedule: "0 2 31 2 *"``는 "2월 31일 새벽 2시"를 의미합니다. 2월에는 31일이 없어서 이 일정은 영원히 도래하지 않습니다. cron 표현식 자체는 유효한 값(일 1~31, 월 1~12)이라 OpenShift는 그대로 받아들이지만, 실제로 자동 트리거되는 일은 없습니다.

**Create**를 클릭합니다. 

이 CronJob은 스케줄이 도래하지 않으므로 저절로 Job을 만들지 않습니다. 필요할 때마다 웹 콘솔에서 수동으로 실행해 봅니다. 
생성 완료되어 현재 웹콘솔에 표시된 `nationalparks-data-load-template` 페이지에서 바로 동작(Action) 드롭다운을 클릭하고 **작업 시작(Start Job)**을 선택해도 되고,
만약 웹콘솔에서 다른 페이지로 이미 이동했다면 **Workloads** → **CronJobs**에서 ``nationalparks-data-load-template``의 오른쪽 ...을 클릭해서 **작업 시작(Start Job)**을 선택해도 됩니다.

[.bordershadow]
image::nationalparks-cronjob-run-job.png[Actions 드롭다운에서 Run Job을 선택하는 화면,link=self,window=blank]

새로 생성된 Job을 확인합니다:

[.bordershadow]
image::nationalparks-cronjob-created-job.png[생성된 Job을 확인하는 화면,link=self,window=blank]

**Run Job**을 클릭할 때마다 이렇게 새로운 Job이 하나씩 만들어지는 것을 확인할 수 있습니다. YAML을 다시 작성할 필요 없이, 필요할 때마다 버튼 클릭 한 번으로 같은 작업을 반복 실행할 수 있는 것입니다. 실습이 끝나면 템플릿을 정리합니다:
