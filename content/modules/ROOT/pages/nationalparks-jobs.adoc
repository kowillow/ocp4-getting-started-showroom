= 일회성 작업과 예약 작업: Job과 CronJob
:navtitle: 일회성 작업과 예약 작업: Job과 CronJob

include::vars.adoc[]

지금까지 ``/ws/data/load``를 브라우저에서 직접 열어 데이터를 적재했습니다. 이런 일회성 작업을 사람이 매번 브라우저를 열어 수행하는 대신, Kubernetes 오브젝트로 자동화해 보겠습니다. 앞선 모듈에서 배운 ``/ws/healthz/`` 상태 확인 경로도 CronJob으로 주기적으로 확인하도록 만들어 보겠습니다.

[#jobs_and_cronjobs]
== 배경 지식: Job과 CronJob

**Deployment**는 Pod가 항상 실행 중인 상태를 유지하도록 설계되었습니다. 하지만 "한 번 실행하고 끝나는" 작업, 예를 들어 데이터 마이그레이션이나 배치 처리에는 어울리지 않습니다. 이런 작업을 위한 오브젝트가 **Job**입니다.

* **Job**은 지정된 완료 조건(기본은 1회 성공)을 만족할 때까지 Pod를 실행합니다. 실패하면 ``restartPolicy``와 ``backoffLimit`` 설정에 따라 재시도합니다.
* **CronJob**은 cron 표현식으로 지정한 일정에 따라 Job을 반복 생성합니다.

Deployment(상시 실행, 재시작하면 안 됨)와 Job(완료되면 끝, 재시작 대신 재시도)의 차이를 기억해 두면 어떤 상황에 무엇을 쓸지 결정하기 쉬워집니다.

[#automate_data_load]
== 실습: 데이터 적재를 Job으로 자동화하기

**Workloads** → **Jobs**에서 **Create** → **From YAML**을 선택하고 다음 YAML을 붙여넣습니다:

[source,yaml,role="copypaste",subs="attributes"]
----
apiVersion: batch/v1
kind: Job
metadata:
  name: nationalparks-data-load
  namespace: {ocp4_starter_project}
spec:
  backoffLimit: 2
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: load-data
          image: registry.access.redhat.com/ubi9/ubi-minimal:latest
          command:
            - curl
            - "-sf"
            - "http://nationalparks.{ocp4_starter_project}.svc.cluster.local:8080/ws/data/load"
----

[#scheduled_healthcheck]
== 실습: CronJob으로 상태 확인 자동화하기

이번에는 앞선 모듈에서 다룬 ``/ws/healthz/`` 경로를 2분마다 자동으로 확인하는 CronJob을 만들어 보겠습니다. **Workloads** → **CronJobs**에서 **Create** → **From YAML**을 선택합니다:

[source,yaml,role="copypaste",subs="attributes"]
----
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nationalparks-healthcheck
  namespace: {ocp4_starter_project}
spec:
  schedule: "*/2 * * * *"
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: healthcheck
              image: registry.access.redhat.com/ubi9/ubi-minimal:latest
              command:
                - curl
                - "-sf"
                - "http://nationalparks.{ocp4_starter_project}.svc.cluster.local:8080/ws/healthz/"
----

[.bordershadow]

**Create**를 클릭합니다. CronJob이 등록되었는지 확인합니다:

[source,bash,role="copypaste"]
----
oc get cronjob
----

몇 분 기다린 후, CronJob이 생성한 Job들의 실행 이력을 확인합니다:

[source,bash,role="copypaste"]
----
oc get jobs -l app.kubernetes.io/created-by=cronjob-controller
----

2분마다 새로운 Job이 생성되고 완료되는 것을 확인할 수 있습니다. 실습이 끝나면 아래 명령으로 CronJob을 정리합니다:

[source,bash,role="copypaste"]
----
oc delete cronjob nationalparks-healthcheck
----
