= 컨테이너에 접속하기
:navtitle: 컨테이너에 접속하기

include::vars.adoc[]

컨테이너는 불변 인프라(immutable infrastructure)로 취급되므로, 일반적으로 SSH를 사용하거나
컨테이너 내부에서 커스텀 명령을 실행하여 컨테이너의 내용을 변경하는 것은 권장되지 않습니다.
그럼에도 불구하고 애플리케이션을 디버깅하는 것과 같은 일부 사용 사례에서는 컨테이너에 접속하여
애플리케이션을 살펴보는 것이 유용할 수 있습니다.

[#remote_shell_to_container_using_cli]
== 실습: CLI를 사용하여 컨테이너에 원격 셸 세션 연결하기

OpenShift에서는 각 컨테이너 내부에 SSH 서비스를 실행할 필요 없이 컨테이너에 원격 셸
세션을 연결할 수 있습니다. 컨테이너 내부에서 대화형 세션을 시작하려면 ``oc rsh`` 명령을
사용하면 됩니다. 먼저 사용 가능한 Pod 목록을 확인합니다:

[source,bash,role="copypaste"]
----
oc get pods
----

다음과 유사한 출력이 표시됩니다:

[.console-output]
[source]
----
NAME                        READY   STATUS    RESTARTS   AGE
parksmap-65c4f8b676-fxcrq   1/1     Running   0          52m
----

이제 Pod 이름을 사용하여 해당 Pod에 원격 셸 세션을 연결할 수 있습니다:

[source,bash,role="copypaste"]
----
oc rsh parksmap-65c4f8b676-fxcrq
----

다음과 같은 출력이 표시됩니다:

[.console-output]
[source]
----
sh-4.2$
----

[NOTE]
====
``oc rsh``가 사용하는 기본 셸은 ``/bin/sh``입니다. 배포된 컨테이너에 **sh**가
설치되어 있지 않고 다른 셸(예: **bash**)을 사용하는 경우, 실행하는 명령에서 Pod
이름 뒤에 셸 명령을 지정할 수 있습니다.
====

다음 명령을 실행하여 루트 디렉터리의 파일 목록을 확인합니다:

[source,bash,role="copypaste"]
----
ls /
----

[.console-output]
[source]
----
anaconda-post.log  bin  dev  etc  home  lib  lib64  lost+found  media  mnt  opt  parksmap.jar  proc  root  run  sbin  srv  sys  tmp  usr  var
----

앞서 언급했던 default Service Account를 기억하시나요? 다음 명령으로 해당 Service Account가 컨테이너에 주입한 토큰을 확인할 수 있습니다:

[source,bash,role="copypaste"]
----
cat /var/run/secrets/kubernetes.io/serviceaccount/token
----

== 실습: 웹 콘솔을 사용하여 컨테이너에 원격 셸 세션 연결하기

OpenShift 웹 콘솔에서도 CLI를 사용하지 않고 컨테이너의 터미널 세션에 편리하게 접근할 수 있습니다.

웹 콘솔을 통해 Pod의 터미널에 접근하려면 Topology 화면으로 이동하여 ``parksmap`` 항목을 클릭한 후 **Pod**를 클릭합니다.

[.bordershadow]
image::parksmap-rsh-dev-console-pod.png[Topology에서 parksmap 항목의 Pod를 클릭하는 화면,link=self,window=blank]

선택한 Pod의 정보를 확인하는 화면에서 **Terminal** 탭을 클릭하여 셸 세션을 엽니다.

[.bordershadow]
image::parksmap-rsh-applications-pods-terminal.png[Pod 세부 정보에서 Terminal 탭으로 셸 세션을 여는 화면,link=self,window=blank]

CLI를 사용했을 때와 동일한 명령을 실행하여 웹 콘솔 기반 터미널이 어떻게 동작하는지 확인해 보세요.

계속 진행하기 전에, Pod와의 연결을 종료합니다:

[source,text,role="copypaste"]
----
exit
----

== 실습: 컨테이너에서 명령 실행하기

원격 셸 외에도 ``oc exec`` 명령을 사용하여 이미 실행 중인 컨테이너에서
원격으로 명령을 실행할 수 있습니다. 이 방식은 셸이 설치되어 있을 필요는 없으며, 원하는
명령이 존재하고 실행 경로에 있기만 하면 됩니다.

``parksmap`` 애플리케이션의 JAR 파일만 확인하려면 다음을 실행하세요:

[source,bash,role="copypaste"]
----
oc exec parksmap-65c4f8b676-fxcrq -- ls -l /parksmap.jar
----

다음과 같은 결과가 표시됩니다:

[.console-output]
[source]
----
-rw-r--r--. 1 root root 39138901 Apr  1 16:54 /parksmap.jar
----

[NOTE]
====
``oc exec`` 명령에서 ``--`` 구문은 exec의 옵션이 끝나고 실제로 실행할 명령이
시작되는 지점을 구분합니다. 자세한 내용은 ``oc exec
--help``를 확인하세요.
====

``oc rsh`` 명령으로 실행할 셸 명령을 직접 지정할 수도 있습니다:

[source,bash,role="copypaste"]
----
oc rsh parksmap-65c4f8b676-fxcrq whoami
----

다음과 같은 결과가 표시됩니다:

[.console-output]
[source]
----
1000580000
----

[NOTE]
====
보안상의 이유로 OpenShift는 기본적으로 Dockerfile에 지정된 사용자로 컨테이너를
실행하지 않는다는 점을 이해하는 것이 중요합니다. 실제로 OpenShift가
컨테이너를 실행할 때 사용자는 무작위로 지정됩니다.

OpenShift 사용자가 root(또는 특정 사용자)로 실행되기를 기대하는 컨테이너
이미지를 배포할 수 있도록 하려면 약간의 설정 변경이 필요합니다. OpenShift의
link:{ocp4_starter_openshift_docs}/html/images/creating-images[컨테이너 이미지 가이드라인^]에서
더 자세한 내용을 확인할 수 있습니다.
====
