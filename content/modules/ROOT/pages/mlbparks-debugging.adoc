[#port_forwading_and_debugging]
== 배경 지식: 포트 포워딩과 디버깅
앞서 pod에 원격 셸로 접속했던 것처럼, 로컬 머신과 pod 사이에 포트 포워딩을 설정할 수도
있습니다. 이는 pod에서 실행 중인 데이터베이스에 연결하거나, 외부에 공개하고 싶지 않은 관리용 웹
인터페이스를 확인하거나, 지금 우리가 하려는 것처럼 애플리케이션 서버를 실행 중인 JVM에 디버거를
연결하는 등의 작업에 유용합니다.

애플리케이션 서버의 디버깅 포트를 포트 포워딩하면, IDE에서 디버거를 연결하여
실시간으로 실행 중인 pod 안의 코드를 실제로 한 단계씩 살펴볼 수 있습니다. 기본적으로 EAP는
디버그 모드가 아니므로, 먼저 디버그 포트를 켜야 합니다.

[#enabling_debugging_in_eap_on_openshift]
== 실습: OpenShift에서 EAP 디버깅 활성화하기

디버깅을 켜는 것은 매우 간단합니다. 지금 사용 중인 EAP S2I 컨테이너는 디버그 포트를
활성화할지 여부를 제어하는 환경 변수를 확인합니다. 배포에 환경 변수만 설정해 주면
됩니다.

[source,bash,role=copypaste]
----
oc set env deployment/mlbparks DEBUG=true
----

이렇게 하면 MLBparks pod가 강제로 재배포되며, 이번에는 JDWT 트랜스포트가 활성화되어 8787 포트로
서비스됩니다.

pod에 직접 연결해서 디버깅할 수도 있지만, pod 인스턴스가 하나뿐일 때는 Service를 통해 포트 포워딩을
설정하는 것이 편리할 수 있습니다(pod 이름은 바뀌지만 Service 이름은 고정되어 있기 때문입니다). <<Exercise: Port-Forwarding from the pod to our local machine,실습: Pod에서 로컬 머신으로 포트 포워딩하기>>를 참고하세요.

[#port-forwarding_from_svc_to_our_local_machine]
== Service를 통해 로컬 머신으로 포트 포워딩하기

해당 service를 좀 더 자세히 살펴보겠습니다:

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc describe svc/mlbparks
----

[.console-output]
[source,bash,subs="+macros,+attributes"]
----
Name:              mlbparks
Namespace:         workshop
Labels:            app=workshop
                   component=mlbparks
                   createdBy=mlbparks-template
                   role=backend
                   type=parksmap-backend
Annotations:       openshift.io/generated-by: OpenShiftNewApp
                   service.alpha.openshift.io/dependencies: [{"name":"mongodb-mlbparks","namespace":"","kind":"Service"}]
Selector:          deploymentConfig=mlbparks
Type:              ClusterIP
IP Families:       <none>
IP:                172.21.206.162
IPs:               <none>
Port:              8080-tcp  8080/TCP
TargetPort:        8080/TCP
Endpoints:         172.30.18.203:8080
Port:              8787-tcp  8787/TCP
TargetPort:        8787/TCP
Endpoints:         172.30.18.203:8787
Session Affinity:  None
Events:            <none>
----

이제 배포가 디버깅용으로 설정되었으므로 8787 포트에서 대기하게 됩니다. 이제 이 service의 해당 포트로
포트 포워딩을 설정합니다(그러면 다시 pod로 전달됩니다).

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc port-forward svc/mlbparks 8787:8787
----

이제 ``localhost:8787``로 연결하면 pod 안에서 실행 중인 mlbparks 인스턴스로 전달됩니다.

NOTE: 포트 포워딩은 ``oc port-forward`` 명령이 실행되는 동안에만 유지됩니다. 포그라운드에서 실행하고 있으므로 kbd:[CTRL+c](Mac에서는 kbd:[CMD+c])를 눌러 포트 포워딩을 중지할 수 있습니다.

이제 해당 포트에 연결할 디버거만 찾으면 됩니다.

[#setting_up_remote_debugging]
== 원격 디버거 연결하기

소스 코드를 디버깅하려면 원하는 IDE(아래는 IntelliJ 기준 안내)를 사용하거나 콘솔에서 디버깅할 수 있습니다. 상황에 맞는 탭을 선택하세요.

[tabs]
====
Console::
+
--

.NOTE
****
이 안내는 Java 명령줄 디버거인 ``jdb``가 설치되어 있다고 가정합니다. 설치되어 있지 않다면, Maven과 ``jdb``가 모두 설치된 docker 컨테이너를 실행하는 방법을 xref::mlbparks-binary-build.adoc#docker_for_maven[여기서] 확인할 수 있습니다. 해당 안내를 완료했다면, <<Port-Forwarding through a Service to our local machine,위에서 설명한>> 대로 컨테이너 안에서 포트 포워딩을 설정하세요. 그런 다음 컨테이너 안에서 아래 안내를 따르세요.
****

. 로컬에 클론한 mlbparks git 저장소의 루트에서 다음 명령을 실행합니다:
+
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
jdb -sourcepath $(pwd)/src/main/java -attach localhost:8787
----
+
[.console-output]
[source,bash,subs="+macros,+attributes"]
----
Set uncaught java.lang.Throwable
Set deferred uncaught java.lang.Throwable
Initializing jdb ...
>
----
+
. 다음으로, 디버거에서 다음 명령을 실행하여 ``BackendController`` 클래스에 중단점을 설정합니다:
+
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
stop in com.openshift.evg.roadshow.rest.BackendController.get
----
+
[.console-output]
[source,bash,subs="+macros,+attributes"]
----
Set breakpoint com.openshift.evg.roadshow.rest.BackendController.get
----
+
. mlbparks url로 이동합니다(셸에서 curl을 사용하거나 브라우저에 url을 붙여넣으면 됩니다)
+
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
curl http://mlbparks-workshop.{ocp4_starter_apps_domain}/ws/info
----
+
. 이제 디버거가 ``BackendController.get`` 메서드의 첫 줄에서 "중단"되어 있을 것입니다.
+
[.console-output]
[source,java,subs="+macros,+attributes"]
----
Breakpoint hit: "thread=default task-4", com.openshift.evg.roadshow.rest.BackendController.get(), line=23 bci=0
23            return new Backend("mlbparks", "AMAZING MLB Parks", new Coordinates("39.82", "-98.57"), 5);
----
+
. jdb 명령들을 자유롭게 사용해 보세요. 몇 가지 예시는 다음과 같습니다:
** ``list``: 중단점 주변 소스를 더 넓게 확인합니다
** ``where``: 스레드의 현재 스택을 출력합니다
** ``print``: 변수의 값을 출력합니다. 예를 들어 ``print this``로 BackendController를 문자열로 확인할 수 있습니다
** ``cont``: 프로그램 실행을 계속합니다
--
IntelliJ::
+
--
IntelliJ에서 원격 디버깅을 설정하는 것은 매우 쉽습니다. 먼저 실행/디버그 설정을 편집합니다.
Run 메뉴(kbd:[ALT + u]) 아래에서 edit configurations를 선택합니다. 새 설정 대화 상자가 표시됩니다.

왼쪽 상단의 플러스(+) 버튼을 클릭하고 아래로 스크롤하여 Remote JVM Debug를 선택합니다.

image::deprecated/mlbparks-debugging-intellij-debug-new.png[IntelliJ run and debug configurations dialog,link="self",window=_blank]

표시되는 대화 상자 페이지에서 상단의 이름을 "on OpenShift"나 원하는 이름으로 변경합니다. 그런 다음
오른쪽 하단에서 포트 번호를 8787로 변경합니다. 완료했다면 "OK"를 클릭합니다.

image::deprecated/mlbparks-debugging-intellij-debug-info.png[IntelliJ remote debug configuration with port 8787,link="self",window=_blank]

이제 IntelliJ에서 Debug 아이콘을 클릭하면 디버거가 열리고 OpenShift 위의 pod에 있는 JVM에 연결됩니다.
원하는 어떤 클래스에든 중단점을 설정해 보세요. 평소처럼 익숙하고 편한 방식으로 디버깅할 수 있습니다!

--

[#port-forwarding_from_pod_to_our_local_machine]
== 실습: Pod에서 로컬 머신으로 포트 포워딩하기

포트 포워딩을 하는 것은 매우 간단합니다.

먼저 pod 목록을 확인합니다:
[source,bash,role=copypaste]
----
oc get pods
----

[.console-output]
[source,bash]
----
NAME                             READY   STATUS      RESTARTS   AGE
mlbparks-1-build                 0/1     Completed   0          4d
mlbparks-1-deploy                0/1     Completed   0          4d
mlbparks-1-hook-post             0/1     Completed   0          4d
mlbparks-2-build                 0/1     Completed   0          10m
mlbparks-2-deploy                0/1     Completed   0          9m49s
mlbparks-2-hook-post             0/1     Completed   0          8m59s
mlbparks-3-deploy                1/1     Running     0          25s
mlbparks-3-hcd8g                 0/1     Running     0          10s
...
----

이제 포트 포워딩을 설정할 수 있습니다:

[.console-input]
[source,bash,subs="+attributes,macros+"]
----
oc port-forward mlbparks-3-hcd8g 8787:8787
----

pod의 8787 포트를 로컬 머신의 8787 포트로 포트 포워딩하도록 지정했습니다. 이제 <<Attaching a Remote Debugger,여기>>에서 설명한 대로 원격 디버거를 연결할 수 있습니다.
